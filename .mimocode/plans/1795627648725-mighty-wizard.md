# Что не хватает до рендера камерой

## Ответ (gap analysis)

Пайплайн (WGSL `camera.view_projection * object.model * pos`, bind group 0 = camera,
`RawGpuCamera` с `update()` через `write_buffer`) уже готов. Не хватает трёх вещей —
все в `dum-sandbox/src/main.rs`, **dum-hell не меняется** (там уже есть
`Camera::view_projection_matrix(view)`, `Camera::set_aspect_from_surface`,
`RawGpuCamera::update`, `RawOrchestrator::resize`):

1. **View-матрицы нет вообще.** `Camera` — только проекция; `view_projection_matrix(view)`
   требует view снаружи. Сэндбокс передаёт `Mat4::IDENTITY` (main.rs:30, 49), а
   `self.camera` создаётся и не используется.
2. **Camera не провяана к GPU.** Каждый кадр в uniform пишется identity вместо
   `camera.view_projection_matrix(view)`.
3. **Aspect не обновляется.** `set_aspect_from_surface` не вызывается никогда
   (дефолт aspect = 1.0), `WindowEvent::SurfaceResized` не обрабатывается (main.rs:66) —
   перспектива растягивается на не-квадратном окне.

Решения по scope (от пользователя): view строится в sandbox через
`plam::Mat4::unchecked_look_at_rh` (Camera остаётся projection-only); объём — только
проводка камеры (+ Resized). Ресурсы на кадр и depth не трогаем.

## Изменения — только `dum-sandbox/src/main.rs`

### 1. `start()` (main.rs:21–33)
- После создания камеры: `camera.set_aspect_from_surface(window.size())`
  (`window.size() -> plam::Extent` — уже передаётся в `orchest.resize`).
- Демо-константы камеры (consts в начале файла):
  `EYE = plam::Vec3::unchecked_new(0.0, 0.0, 2.0)`, `TARGET = plam::Vec3::ZERO`,
  `UP = plam::Vec3::unchecked_new(0.0, 1.0, 0.0)`.
- `create_gpu_camera(...)`: передать реальный VP
  (`camera.view_projection_matrix(view)`) вместо `Mat4::IDENTITY`.

### 2. `event()` — обработка ресайза (main.rs:63–66)
Новая ветка матча:
```rust
glumy::WindowEvent::SurfaceResized(extent) => {
    orchest.resize(extent);
    if let Some(camera) = &mut self.camera {
        camera.set_aspect_from_surface(extent);
    }
}
```
(`WindowEvent::SurfaceResized(plam::Extent)` есть в glumy 1.1, checkout 85736a4.)

### 3. `RedrawRequested` — реальный VP в uniform (main.rs:48–51)
Вместо `gpu_camera.update(&orchest.device(), Mat4::IDENTITY)`:
```rust
let view = plam::Mat4::unchecked_look_at_rh(EYE, TARGET, UP);
let vp = camera.view_projection_matrix(view);
gpu_camera.update(&orchest.device(), vp);
```
- `self.camera` — другое поле, чем `&mut self.orchest`: borrow-splitting уже работает
  (как сейчас с `self.gpu_camera`), новых проблем не будет.
- Вынести `update` из замыкания render-pass на строку выше `frame.render_pass(...)`
  (запись uniform до encode — часть проводки камеры).
- Сцену (`triangle_2d`, identity model, red) не меняем.

## Файлы
- `dum-sandbox/src/main.rs` — единственный изменяемый файл.

## Проверка
1. `cargo run -p dum-sandbox` — красный треугольник виден через перспективную камеру
   (камера на z=2 смотрит на треугольник в z=0, fov 90°).
2. Растянуть окно — треугольник НЕ растягивается (aspect обновился через
   `SurfaceResized`).
3. Быстрая проверка view: поменять `EYE` на `(1.0, 0.5, 2.0)` — ракурс должен сдвинуться
   (сейчас матрица вида жёстко identity, этого эффекта нет).
4. `cargo clippy --workspace` — без новых предупреждений.
